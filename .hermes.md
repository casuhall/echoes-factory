# Règles du projet — Echoes Factory

## Principes architecturaux
- KISS par-dessus tout : pas de complexité inutile, pas de sur-ingénierie
- Programmation orientée objet stricte : classes cohérentes, responsabilité unique, encapsulation
- DDD en retrait : utiliser les bounded contexts et les termes métier seulement quand la surface le justifie, pas de forcing
- En cad de doute, demande : si un choix est nécessaire, et que les entrants ne permettent pas de le faire de façon certaine,
demander son avis à l'humain.
- Workflow imposé : fonctionnalité → domaine/services → interface utilisateur → stockage

## Stack technique
- Environnement : navigateur uniquement, pas de serveur Node.js
- Langage : JavaScript simple (ES modules), pas de TypeScript
- Modules : organisés par responsabilité métier, pas par couche technique
- Style : classes bien nommées, méthodes courtes, commentaires uniquement pour le "pourquoi"
- Internationalisation : fichiers JSON dans `locales/`, classe `I18n` dans `app/i18n.js`, dot-notation pour les clés, 4 langues supportées (fr, en, de, es)

## Gestion du stockage
- Mode par défaut : localStorage (accès via promesse pour uniformiser)
- Mode optionnel : Pantry (https://getpantry.cloud/) si l'utilisateur fournit un identifiant
- Abstraction obligatoire : le reste de l'application ne dépend jamais directement de localStorage ou de Pantry
- Règles de transition lors de la première saisie d'un identifiant Pantry :
  1. Lire le contenu du Pantry et les données locales
  2. Si Pantry vide et données locales présentes : transfert silencieux local → Pantry
  3. Si Pantry vide et locales absentes : utilisation silencieuse du Pantry
  4. Si locales absentes et Pantry plein : utilisation silencieuse du Pantry
  5. Si les deux contiennent des données valides : demander à l'utilisateur (garder Pantry / garder local / annuler)
  6. En cas d'erreur de lecture du Pantry : signaler l'erreur, ne pas modifier le stockage
  7. Après association réussie, mémoriser l'identifiant de Pantry pour les sessions suivantes
- Statut : implémenté (storage.js) avec URL pattern /apiv1/pantry/{id}/basket/echoes-factory

## Standards de code
- Pas de duplication : réutiliser la logique existante plutôt que la réécrire
- Méthodes courtes (< 20 lignes)
- Pas d'anticipation prématurée : implémenter seulement ce qui est nécessaire pour la fonctionnalité courante
- Tests manuels documentés si pertinent
- Pas de commit automatique : les commit/push ne peuvent être réalisés que suite à un contrôle humain. L'agent ne doit jamais
exécuter de commit/push sans demande explicite de l'utilisateur.
- La documentation de l'application doit être maintenue à jour pour refléter les changements effectués dans le code.
